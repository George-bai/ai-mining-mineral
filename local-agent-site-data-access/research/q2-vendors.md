## Summary

As of **23 November 2026**, a plant can give a small on-site model access to historian data without sending readings to a vendor cloud. PI Web API, Canary’s Read API, Ignition’s historian functions and Proficy’s read-scoped REST API all provide a way to find tags and retrieve a time range. The plant supplies the model and the connector. The clearest published end-to-end example I found used a local model to find and read WinCC OA datapoints in a **demo project**. [PI Web API](https://docs.aveva.com/bundle/pi-web-api-reference/page/help/getting-started.html) · [Canary Read API](https://helpcenter.canarylabs.com/t/p8ypl9x/using-the-read-api-version-26) · [WinCC OA study](https://www.theseus.fi/bitstreams/585869bd-a8c2-4a1c-83d8-677d42b0f513/download)

The vendor-hosted options differ substantially. **Cognite** documents a read-only MCP server that searches its industrial data model and returns time-series aggregates. **Seeq** lets an external agent call a Seeq agent, which can change a workbook. **AVEVA CONNECT** searches data already published to CONNECT and sends retrieved information to a cloud model. A local MCP client establishes where the connection starts. The tool permissions and the model endpoint determine what can change and where the readings go. [Cognite tool and security reference](https://docs.cognite.com/cdf/build/mcp/security) · [Seeq MCP Server](https://support.seeq.com/latest/cloud/mcp-server) · [AVEVA assistant service description](https://www.aveva.com/content/dam/aveva/documents/legal/service-documents/AVEVA-Industrial-AI-Assistant.pdf)

Below, **MCP** means Model Context Protocol, a way for an assistant to call named tools. Dates are publication, release or revision dates as identified. *Undated* means I could verify the document but could not establish its publication date. The findings describe documented capabilities. I did not test them against a running historian.

## AVEVA PI System, CONNECT and AVEVA Historian

- **PI Web API Reference — AVEVA, updated 14 February 2025.** An on-site application can find PI points, or navigate equipment and its attributes in PI Asset Framework, then request recorded samples, interpolated values or summaries. The API also supports writes. A local agent therefore needs a PI identity limited to the intended reads. The API itself requires no language model. [PI Web API Reference](https://docs.aveva.com/bundle/pi-web-api-reference/page/help/getting-started.html)
- **AVEVA PI Data Infrastructure Service Description — AVEVA, revised 26 February 2026.** PI Server and the PI-to-CONNECT agent run on premises. Sending process data to CONNECT is optional. This establishes two distinct deployment choices for a PI customer: query the site server locally, or publish selected streams to the cloud service. [Service description, pp. 3–4](https://www.aveva.com/content/dam/aveva/documents/legal/service-documents/AVEVA-PI-Data-Infrastructure.pdf)
- **Industrial AI Assistant in CONNECT is now available — Lori Warda, AVEVA, 3 July 2025.** A user can find CONNECT assets and streams without knowing the exact tag name. The assistant combines keyword and semantic search, filters by the user’s permissions and retrieves information for the answer. Its search covers data made available in CONNECT. [AVEVA release article](https://www.aveva.com/en/perspectives/blog/industrial-ai-assistant-in-connect-is-now-available-here-is-how-you-can-get-started/)
- **AVEVA Industrial AI Assistant Service Description — AVEVA, revised 21 April 2026.** The architecture shows retrieved CONNECT data going to Azure OpenAI. The assistant can create visualizations. I found no documented tool here for changing the original PI archive. [Service description](https://www.aveva.com/content/dam/aveva/documents/legal/service-documents/AVEVA-Industrial-AI-Assistant.pdf)
- **System Platform — AVEVA, product page undated.** AVEVA lists an **AVEVA Historian MCP Server (Beta)** for discovering tags, assets and relationships and accessing process data, events and alarms. This is the **System Platform Historian** offering. The page lists on-premises deployment for the platform but leaves the beta’s write controls and the location of model inference unspecified. [System Platform product page](https://www.aveva.com/en/products/system-platform/)
- **AI and MCP in OT — AVEVA, 29 October 2026.** AVEVA listed a **PI** MCP demonstration at its pipeline summit. I could verify the demonstration listing, but not a generally available AVEVA-supplied PI MCP server, its tool permissions or its model-hosting requirements by the cutoff. [AVEVA summit session](https://events.aveva.com/pipeline-summit-amer-2026/session/4460010/ai-and-mcp-in-ot%E2%80%94part-1-technology-security-and-demonstrations)
- **AVEVA PI System MCP Server — Digital-Enginks, open-source v1.0.0 released 6 July 2026.** This independent server runs locally over PI Web API. It searches PI points, browses Asset Framework elements and attributes, and reads time series. Its defaults disable writes, but it includes three optional value-write tools. All callers use one configured upstream PI identity, so that account determines the maximum plant access. The model is supplied separately. [Project tool catalogue](https://github.com/Digital-Enginks/aveva-pisystem-mcp-server/blob/main/docs/tools.md) · [Release history](https://github.com/Digital-Enginks/aveva-pisystem-mcp-server/blob/main/CHANGELOG.md)

## Seeq

- **Seeq APIs and SDKs / SPy tutorial — Seeq, undated manuals.** An existing on-premises Seeq Server exposes the data-access functions used by Workbench. The Python examples show `spy.search` finding signals by metadata, `spy.pull` fetching a selected time interval and `spy.push` writing items into Seeq. A plant could expose just search and pull to its own local model. That is a deployment the APIs enable. [On-premises API manual](https://support.seeq.com/latest/on-premise/seeq-apis-and-sdks) · [SPy tutorial](https://python-docs.seeq.com/user_guide/Tutorial.html)
- **Seeq AI Assistant — Seeq, undated product documentation.** Seeq identifies its own assistant as a SaaS feature. Its managed service routes model requests primarily to OpenAI or Azure AI Foundry. For a SaaS connection to a plant historian, Seeq indexes signal metadata and retrieves and caches requested samples. [Assistant availability and hosting](https://support.seeq.com/latest/cloud/seeq-ai-assistant) · [Datasource architecture](https://support.seeq.com/latest/cloud/introduction-to-datasources)
- **Seeq MCP Server — Seeq, undated, labelled Early Access.** The official endpoint has three tools. An external client can list available agents, run Agent Q or a published custom agent, and retrieve the result. Listing and result retrieval are read-only. Seeq explicitly marks running an agent as capable of changes. Access follows the signed-in user’s permissions. A local client still delegates the work to Seeq. [MCP Server documentation](https://support.seeq.com/latest/cloud/mcp-server)
- **Philadelphia Summit demonstration — Philip Brown, Seeq, 14 October 2026.** A separate 42-tool demonstration searched a workbook, fetched signal samples and statistics, and retrieved intervals when a condition was true. Of 15 calls, two changed the workbook by creating a formula condition and adding it to a worksheet. The data was synthetic. This is unusually clear evidence of what an assistant actually read and what it changed. [Summit deck, slides 19–35](https://engage.seeq.com/philly-summit-october-2026/items/master-deck-philly-summit-pdf)

## Cognite Data Fusion

- **How to Set Up and Configure a PI Extractor on a Windows Virtual Machine — Anastasiia Vlasenko, Cognite, 4 June 2025.** The extractor discovers PI time series and sends them to the customer’s Cognite Data Fusion project. The connector can run beside PI, but the Industrial MCP route queries the data made available in that cloud project. [Cognite PI extractor instructions](https://hub.cognite.com/extractors-407/how-to-set-up-and-configure-a-pi-extractor-on-a-windows-virtual-machine-cognite-official-5130)
- **September 2026 release — Cognite, 8 September 2026.** Cognite announced **Industrial MCP in public preview** for querying the governed industrial data model with the user’s permissions. Public preview is the release status I could verify by the cutoff. [Cognite release announcement](https://resources.cognite.com/en/resources/blog/cognite-september-2026-release)
- **Industrial MCP security and tool inventory — Cognite, undated.** The server is **read-only**, runs in the same cloud cluster as the CDF project, and uses the signed-in user’s permissions. It can inspect schemas, search and retrieve records, follow the industrial data model and request **aggregates for 1–10 time series over a specified interval**. The documented tool does not return arbitrary raw samples. Document Q&A and summarization can invoke a model in the project’s cloud region. [Security and tool inventory](https://docs.cognite.com/cdf/build/mcp/security)

## Canary Labs

- **Using the Read API, version 26 — Canary Labs, manual undated.** An on-site client can browse tags in Canary Views, read tag properties and request raw samples or interval aggregates between two times. With Tag Security enabled, the token’s user needs read permission on the View. Canary documents a separate Write API. A local model can use the read interface through a plant-supplied connector. Version 26.6 was released **17 August 2026**. [Read API](https://helpcenter.canarylabs.com/t/p8ypl9x/using-the-read-api-version-26) · [Worked queries](https://helpcenter.canarylabs.com/t/x2ypl5z/read-api) · [Write API](https://helpcenter.canarylabs.com/t/g9ypl98/using-the-write-api-version-26) · [Version release](https://helpcenter.canarylabs.com/t/35yj3xl/release-v26-6)
- **MCP for Historians — CSE ICON, undated pilot offering.** This third-party Windows service runs on the private network. For Canary 25.4 and later, it uses each user’s Canary token to search Views, browse assets, read history, annotations and events, and calculate aggregates. CSE ICON says the tools cannot change values or configuration or acknowledge alarms. Its PI variant uses the Asset Framework SDK under one Windows service identity. The service returns results to the chosen model, whose location is a separate deployment decision. [CSE ICON product specification](https://products.cse-icon.com/historian-mcp/)

## Emerson AspenTech IP.21

- **Aspen InfoPlus.21 — AspenTech, 2025.** AspenTech describes its IP.21 integration with Inmation as bidirectional, including automatic tag creation. Connecting the two products therefore does not itself create a read-only boundary. [IP.21 brochure, AT-0742](https://www.aspentech.com/-/media/aspentech~/brochure/pdfs/fy26/q1/at-0742-bro-infoplus21.pdf)

Discovering a tag does **not** start copying its values; replication must be enabled for that tag. A local reader can query the resulting objects for historical values, quality and timestamps. The history endpoint checks read permission per object, and the write endpoint requires separate write permission. [IP.21 browse and replication](https://otdfdocs.inmation.com/features/1.3/connectivity/ip21/grpc-server.html) · [Raw-history API](https://otdfdocs.inmation.com/api/1.3/webapi/endpoints/syslib.api-readrawhistoricaldata.html) · [Endpoint permissions](https://otdfdocs.inmation.com/api/1.3/webapi/authentication.html)
- **AVA industrial AI platform launch — Emerson, 11 May 2026.** Emerson says AVA uses Inmation’s contextualized operating data and that four decision-support advisors were available at launch. Inmation can run at the edge, on premises or in the cloud. The announcement leaves AVA’s model location, individual advisors’ access to IP.21 tags and historian write permissions unspecified. ## Community OPC UA servers and an appliance example

- **OPC 10000-11, Historical Access — OPC Foundation, v1.05.04 published 15 October 2024.** A raw history read requests stored values, quality and timestamps for a time interval. This is the test to apply to an “OPC UA MCP” claim: browsing nodes, reading the current value or subscribing to future changes does not retrieve yesterday’s measurements. [Specification and date](https://reference.opcfoundation.org/specs/OPC-10000-11) · [Raw history-read definition](https://reference.opcfoundation.org/specs/OPC-10000-11/6.5.3)
- **OPCUA-MCP — IndustriAgents, open-source v0.6.0 released 14 October 2026.** It browses and searches the OPC UA address space, reads current values, and can request history where the underlying server supports it. The default `observe` profile excludes value writes and method calls. The connector can run locally. The deployment must separately supply a local model if results are to stay on site. [Release](https://github.com/IndustriAgents/OPCUA-MCP/releases/tag/v0.6.0) · [Tools and profiles](https://github.com/IndustriAgents/OPCUA-MCP/blob/main/packages/server-python/README.md#tools)
- **opcua-mcp — Kukapay, first package release 27 March 2025.** The inspected source browses child nodes and exposes single and bulk **current-value reads and writes**. I found no registered tool for historical time-range retrieval. It illustrates why a generic OPC UA connector is insufficient evidence for either historian access or read-only operation. [Package history](https://pypi.org/project/opcua-mcp/) · [Registered tools in source](https://github.com/kukapay/opcua-mcp/blob/main/main.py)
- **1848ETC-HST Product User Guide — Real Time Automation, rev. 4.5.14947, manual undated; native MCP announced 22 June 2026.** The appliance stores history and hosts MCP on site. The guide shows an assistant discovering the database contents and querying **24 hours of boiler records**. Historian writes and deletes have separate switches, both off in the example. The demonstrated client uses Claude Desktop with Sonnet, so the example verifies an on-site historian and a genuine history query, while leaving fully local inference unverified. [User guide, pp. 78–84](https://www.rtautomation.com/userguides/1848ETC-HST_Userguide.pdf#page=78) · [Dated product announcement](https://www.rtautomation.com/press/historian-modbus-mcp-ai/)
