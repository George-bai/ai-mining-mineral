1. **CONFIRMED** — Korpela’s ABB Ability History prototype ran “30 test cases.” It identified the required variables in **18/30** and converted relative times to timestamps correctly in **30/30**. Users could “only use the interface for data fetching.” [Korpela, pp. 1, 36–37 (Table 2), 39–40](https://trepo.tuni.fi/bitstream/handle/10024/226285/KorpelaOssi.pdf?isAllowed=y&sequence=2)
2. **WRONG** — Dranca et al. used one RTX 4090 and the cheese factory’s live InfluxDB. Only **CodeGemma-2B using Flux** executed **8/8** time-sensitive aggregation queries with **0/8** exact matches. LLaMA3-3B using InfluxQL executed **8/8** with **1/8** exact matches. [Dranca et al., §§4.3.3, 4.3.5, Tables 11–13](https://www.frontiersin.org/journals/artificial-intelligence/articles/10.3389/frai.2026.1764367/full)
3. **CONFIRMED** — Granite-3-8B completed **9/20** tasks with zero examples and **20/20** with “all 17 curated trajectories.” The tool sequence is “Sites” → “Assets” → “Sensors” → “Histories.” [Rayfield et al., Tables 1 and 5](https://aclanthology.org/anthology-files/pdf/emnlp/2025.emnlp-industry.24.pdf)
4. **CONFIRMED** — Mulayim et al. used GPT-4o on three FLEXLAB test-cell questions and “ran each question five times.” Table 1 scores them **5/5, 5/5, 3/5**. Its footnote qualifies the second **5/5**: in three runs the plot was correct, but the verbal answer covered only one sensor. [Mulayim et al., Table 1 and footnote +](https://eta-publications.lbl.gov/sites/default/files/2025-07/extraction_and_analysis_of_time_series_data.pdf)
5. **CONFIRMED** — Siregar ran Qwen3-14B locally against a WinCC OA demo project. Among **235** queries requiring tools, the logs showed “0 instance where the model generated wrong syntax.” The prototype supported setter tools, and “The operator mediates all critical decisions.” [Siregar, §§6.2.1, 6.2.3, 6.3.3.1, 6.4.6](https://www.theseus.fi/bitstreams/585869bd-a8c2-4a1c-83d8-677d42b0f513/download)
6. **CONFIRMED** — Hasan et al. ran Qwen3-14B locally on one **24 GB** GPU using archived SCADA data from one operating **2 MW** turbine. The evaluation used **24** held-out operator questions and reported “91.7% accuracy on health-checks,” the present-state category. [Hasan et al., Abstract, §4.1, Tables 4–5](https://doi.org/10.1016/j.egyai.2026.100828)
7. **CONFIRMED** — The coal-mine “Historical Alarm Data Retrieval Agent” queried past gas alarms “By executing SQL queries.” Table 4 reports **0.87** as the overall average accuracy for gas risk-level classification. [Sun, Han and Liu, §4.3.2 and Table 4](https://www.mdpi.com/2079-9292/14/2/379)
8. **CONFIRMED** — The historical test used **540 days** of data on Formant-managed infrastructure with “read-only access and no connection to live controls.” Across **47** historical alarms, the reported average reduction in time to resolution was **60%**. [Intel case study, “PoC Overview” and Table 1](https://media26.connectedsocialmedia.com/intel/21461/Proving_Value_Context_AI_Driven_Industrial_Operations.pdf) · [Formant, test-bed description](https://www.formant.ai/case-studies/intel-foundry)
9. **CONFIRMED** — Nexa describes a “ChatBot basado en Gemini” using the “framework Langchain” to query databases at the Cerro Lindo concentrator. The project entry gives no accuracy figure. [Nexa Resources Perú, *Memoria Anual 2024*, p. 107](https://www.smv.gob.pe/ConsultasP8/temp/Memoria%20Anual%202024%20Nexa%20Peru.pdf)
10. **CONFIRMED** — NCSC describes replication from the OT historian to a DMZ historian through a “unidirectional, secure transfer mechanism.” IT systems query the DMZ historian through a “secure HTTP-based API” with “strong authentication.” [NCSC, Principle 4, “Industrial protocols,” final paragraph](https://www.ncsc.gov.uk/collection/operational-technology/secure-connectivity/principle-4)
